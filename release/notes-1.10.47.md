# Klinto 1.10.47 — конфиденциальность в KMesh без Hub

Выбор ключа при отправке через KMesh (в порядке приоритета):
1. **Секретный чат** — E2E-ключ с устройства (с Hub не синхронизируется), в кластере и через шлюз.
2. **Закэшированный постоянный серверный ключ чата** — используется всегда, даже без шлюза.
3. **Шлюз доступен** — ключ запрашивается у Hub через KMesh (CHAT_KEY_REQ), сообщение уходит под серверным ключом.
4. **Ключа нет** — личный чат шифруется **ключом пары пользователей**: ECDH ключей аккаунтов (P-256) + HKDF по chatId.
   Модули и Hub его не знают. Hub такой конверт (`text:pair`) не хранит, только пересылает узлам собеседника.
5. **Нет ни одного ключа** — сообщение в эфир не уходит; ждёт в очереди до доступа к Hub.
   Исключение: публичный канал (пост и так публичный) — уходит в кластер открытым.

Синхронизация: очередь отправителя хранится на устройстве и выгружается на Hub под серверным ключом, как
только Hub доступен (интернет или шлюз KMesh); серверная копия заменяет mesh-копию у собеседников.

Подготовка: публичные ключи аккаунтов собеседников личных чатов кэшируются, пока есть интернет.

Hub 1.4.5: конверты под ключом пары не сохраняются, только пересылаются.
Сервер: исходники сборщика прошивок сохранены в /opt/swarmgram/services/firmware-builder (сборки из образа
получат NimBLE, C5, CDC и раздел для ESP32); ядро прошивки на сервере — build 174.
