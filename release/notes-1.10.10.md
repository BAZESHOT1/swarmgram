# Klinto 1.10.10 — KMesh-отправка офлайн и статус кластера

Дата: 16 ноября 2026 года.

## KMesh-сообщения

- При офлайне текст сразу уходит через KMesh_v1 — ещё до локального
  шифрования серверного чата. Раньше без интернета ключ серверного чата
  получить было нельзя, и сообщение превращалось в «Зашифрованное сообщение».
- `localFallback` сохраняет текст: даже если ключ чата ещё не получен, пузырь
  показывает сообщение, а не замок.
- Архивные KMesh-сообщения без `objectId` расшифровываются из
  `header.ciphertextB64`.
- `clientId` едет в `header`; Hub возвращает его в истории и обновляет header
  при повторной синхронизации — оптимистичное сообщение склеивается с архивным.

## Нижний док

- Если подключён модуль, доступность Hub определяет **шлюз кластера**
  (`transportGateway`), а не интернет телефона.
- Есть шлюз — капсула «Соединение» скрыта; нет — «Кластер офлайн».

## Страница информации о чате

- Без сети данные берутся из локального кэша, экран открывается вместо ошибки,
  сверху пометка «Данные чата из локального кэша: работает KMesh».

## Прошивка 148

- Периодический INFO раз в 15 секунд: `gateway`/`queue` обновляются в
  приложении без переподключения.
- INFO повторяется после HELLO; уведомления BLE отправляются с паузой 28 мс,
  чтобы длинный кадр не обрывался на переполнении очереди notify.
- v1 INFO содержит `hardwareId`, `firmware`, `battery`.
