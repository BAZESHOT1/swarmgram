# Klinto 1.10.36 — прогресс KMesh и отправка без ключа на iOS

Дата: 17 ноября 2026 года.

## 1. Почему на iPhone был только «часик»

При отправке в чат, для которого ещё не был получен постоянный ключ (типично
для свежей установки iOS), `encryptForChat` выбрасывал исключение, и сообщение
уходило в `localFallback` — то есть **вообще не в KMesh**. В пузыре оставался
обычный индикатор ожидания без прогресса.

Исправлено:

- при ошибке получения ключа текст теперь сразу уходит через KMesh
  (`sendTextViaMesh`), а не в локальный fallback;
- KMesh сам запрашивает постоянный ключ (`CHAT_KEY_REQ`) у Hub и, если ключа
  нет, отправляет компактный plaintext-RPC внутри запечатанного кластерного
  пакета;
- outbox сохраняет сообщение и при появлении сети шифрует его постоянным ключом
  и сохраняет в Hub.

## 2. Прогресс KMesh с самого начала

Раньше полоса и статус появлялись только после первого события записи в BLE.
Теперь сообщение сразу получает фазу:

- `Подготовка KMesh…`
- `Получаем постоянный ключ чата…`
- `Отправка в модуль… X/Y Б`
- `Передано в модуль · ожидание подтверждения`
- `Шлюз принял · ждём подтверждения Hub…`
- `Сохранено в Hub`

Полоса заполняется по реально записанным байтам кадра, а если размер ещё
неизвестен — показывается текст фазы.

## 3. Быстрый fallback при «залипшем» online

Если телефон считает, что интернет есть, но HTTP фактически не проходит,
запросы чата/загрузки/регистрации ограничены ~4 секундами при подключённом
модуле. После этого сообщение уходит через KMesh, и прогресс появляется без
12-секундного ожидания.
