# Klinto 1.10.9 — стабильный KMesh через BLE

Дата: 16 ноября 2026 года.

## Подключение модуля по BLE

- Скан теперь ловит имя `KL-*` из scan response (`allowDuplicates`), даже если
  первый пакет рекламы пришёл без `localName`.
- Если модуль уже подключён системой и перестал рекламироваться, приложение
  берёт его из `connectedDevices`/известных устройств и подключается напрямую.
- Ручное «Найти по Bluetooth» больше не возвращает молчаливую ошибку, пока
  автоскан занят: подключение ждёт завершения автоскана.
- Первый HELLO отправляется после паузы 250 мс и повторяется 4 раза; вместе с
  legacy-кадром уходит и KMesh_v1 HELLO.
- Транспорт понимает KMesh_v1 INFO (nodeId/gateway/queue) и собирает из него
  карточку модуля, даже если legacy INFO не пришёл.

## Сообщения через KMesh

- Архивные KMesh-сообщения без `objectId` теперь расшифровываются из
  `header.ciphertextB64`, а не превращаются в «Зашифрованное сообщение».
- `clientId` едет через KMesh в `header`, Hub отдаёт его в истории: оптимистичное
  сообщение склеивается с архивным без дубля и без потери текста.
- После синхронизации сообщение остаётся в чате с текстом.

## Диагностика

- BLE-транспорт пишет короткие строки `[ble]` в logcat (ReactNativeJS): скан,
  connect, HELLO, приём чанков, INFO/таймаут.

## Прошивка

- `fw_build = 146` для ESP32-C3 и ESP32.
- INFO (legacy и v1) повторяется 3 раза с интервалом 350 мс: Android иногда
  подтверждает подписку на notify уже после первого HELLO.
- v1 INFO содержит `hardwareId`, `firmware`, `battery`, `gateway`.
- BLE-логи `[ble] connected/rx/disconnected` в UART.
