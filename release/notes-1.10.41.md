# Klinto 1.10.41 — прошивка 171: BLE больше не отваливается (логика по BitChatRelay / Esp-Wifi-Ble-Now)

Симптом: носимый модуль подключается по BLE и через ~5 с отключается.

Причина: пока модуль не привязан к шлюзу, он ищет соту, перескакивая по Wi-Fi-каналам каждые 160 мс
с передачей проб. Эти скачки отбирают эфир у BLE-соединения (общий радиотракт ESP32) → supervision timeout.

Что взято из референсных проектов (jorgeavilasuarez/BitChatRelay, HamzaYslmn/Esp-Wifi-Ble-Now):
- **Канал закреплён, пока подключён телефон**: при BLE-клиенте модуль не прыгает по каналам.
  Остаётся на последнем рабочем канале (хранится в NVS, `last_ch`) и раз в 3 с шлёт одну пробу;
  шлюз отвечает маяком — модуль фиксируется без обхода.
- Скан при старте начинается с последнего рабочего канала.
- BLE: единственное соединение, реклама на время подключения выключена, параметры 20–50 мс /
  latency 0 / supervision 5 с, TX 9 дБм; приоритет эфира BLE (`esp_coex_preference_set`) на время подключения.
- ESP-NOW: PS_NONE, LR-PHY на STA (b/g/n + LR) у носимого и шлюза.
- В логе причина разрыва: `[ble] disconnect reason=…`.

Замечание: режим LR-скорости broadcast (`esp_now_set_peer_rate_config`) на стенде C3-шлюз + ESP32 подвешивал
mesh-задачу шлюза через ~5 с, поэтому выключен (`KL_ESPNOW_LR_RATE=0`); LR-PHY приёма включён.

Проверено на железе (ESP32 Lite — носимый, C3 Super Mini — шлюз), 100 с: захват соты, 18 маяков подряд
(gw_age ≈ 1.4 с), 11 выгрузок на Hub, 0 разрывов Wi-Fi шлюза. Сборка также проверена для C6, S3, C5.
