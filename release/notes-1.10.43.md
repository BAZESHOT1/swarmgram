# Klinto 1.10.43 — отправка через KMesh без интернета

По логам приложения и модуля: связь телефон ↔ модуль ↔ шлюз ↔ Hub работает (поиск через KMesh:
`[rpc] send ok=1` → `[TRACE 4/4] HUB->GW->NODE->BLE delivered` → `RPC_DOWN op=11`). Сообщение при этом не уходило:

1. **Приложение ждало HTTP.** При `transportKnown=false` и модуле на связи отправка сначала пыталась достучаться
   до сервера (ключ чата) и висела ~100 с, прежде чем уйти в mesh. Теперь, если модуль подключён, а интернета нет
   (или он не подтверждён), HTTP не ждём — сразу KMesh.
2. **Шлюз с интернетом = «интернет» для KMesh.** Флаг `toInternet` ставился только при интернете у телефона;
   теперь и когда модуль видит шлюз. Ключ чата запрашивается у Hub через KMesh (ожидание до 5 с, было 2).
3. **Hub отклонял синхронизацию очереди** (`/v1/kmesh/v1/sync` → 400 `invalid_receiver_node`): получатель
   «шлюз кластера» (node 1) считался недопустимым. Сообщения, ушедшие через mesh, не сохранялись у получателя.
   Hub 1.4.2: допустимо `receiver_node_id ≥ 1`.
