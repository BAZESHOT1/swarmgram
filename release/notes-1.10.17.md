# Klinto 1.10.17 — статус шлюза, владелец модуля, переподключения, KMesh и фон

Дата: 17 ноября 2026 года.

## 1. Шлюз больше не «офлайн» в списке модулей

Найдены две причины:

- **Шлюз не выходил в интернет.** В сборке был зашит тестовый AP `test`
  (`wifi failed ssid=test`), а Wi-Fi, сохранённый приложением, прошивка
  игнорировала. Теперь SSID/пароль читаются из NVS с приоритетом над сборкой,
  `SET_CONFIG` применяется сразу (`WiFi.begin` + переподключение), а при
  обрыве выполняется `WiFi.reconnect()`.
- **Hub считал онлайн только по REST-check-in.** Теперь модуль считается
  онлайн и по свежей KMesh-активности (`kmesh_v1_gateways`/`presence` ≤ 4 мин).
  `node_id` вычисляется из `hardwareId` той же формулой FNV-1a, что в прошивке
  (поддержан старый 8-hex формат).

Проверено: `[TRACE 3/4] GW->HUB: uplink ok status=200`, в БД свежие
`kmesh_v1_gateways` (2084071220) и `kmesh_v1_presence` (481660464).

## 2. «Модуль не мой» на втором телефоне с тем же аккаунтом

- Приложение всегда подтягивает идентичность аккаунта (`blePrefix`, `netId`)
  с Hub и обновляет постоянный кэш при каждом сканировании.
- Дополнительно загружается список модулей аккаунта (`user_modules`): если
  `mod6` найденного модуля есть в списке, он считается своим — даже если в
  BLE-имени оказался другой/устаревший префикс.
- Прошивка хранит `owner_prefix`, `owner_net`, `owner_epoch` и полный конфиг
  (роль, распиновка, тип) в NVS; конфиг сохраняется при загрузке и при смене
  владельца. Буфер NVS-конфига увеличен до 2048 байт.
- При первом подключении свободного модуля префикс берётся из аккаунта.

## 3. Постоянные переподключения носимого модуля

- Ошибка подписки notify (в том числе отмена при плановой переподписке)
  больше не трактуется как разрыв: disconnect приходит только из
  `onDisconnected`.
- Переподписка на `a5c1`/`a5c3` раз в 20 секунд возвращает доставку без
  переподключения.
- Переименование модуля (SET_OWNER) не рвёт активное BLE-соединение: имя
  применяется после disconnect в clientTask.

## 4. Отправка через KMesh

- Главная причина — шлюз без интернета (см. п.1): uplink не уходил в Hub.
  После исправления Wi-Fi архив и presence идут на Hub (`uplink ok 200`).
- Ключ чата для KMesh: если E2EE-ключа нет, используется сохранённый ключ Hub
  (`server`-чаты). Раньше офлайн-отправка падала с `chat_key_missing`.
- Исправлено поле ответа `/kmesh/v1/modules`: клиент читал `claims` вместо
  `incoming`.

## 5. Фон на экране «Чаты»

- Убран градиент `bottomFade` под списком.
- Каркас на маршруте «Чаты» теперь чёрный: пропала светлая рамка вокруг
  тёмного экрана (проверено визуально).

## Прошивка

- Wi-Fi из NVS + переподключение + скан сетей в логе (`wifi scan: N networks`).
- NVS-конфиг 2048 байт, сохранение при загрузке/смене владельца.
- legacy INFO: `nodeId`, `mobile`, `bcn`, `gwAge`; без фиктивного `publicId`.
- BLE для wearable/repeater на esp32/c3/s3/c6; esp32s2 — без BLE.
