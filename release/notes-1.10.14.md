# Klinto 1.10.14 — мобильный шлюз доведён до конца

Дата: 16 ноября 2026 года.

## Что мешало мобильному шлюзу

- Приложение не знало `node_id` модуля, пока не придёт KMesh_v1 INFO. На
  практике этот INFO терялся после первого notify-всплеска, `getNodeId()`
  оставался 0, и `INET_STATUS`/`PROXY_UP` вообще не отправлялись.
- Теперь `node_id` приходит в legacy INFO (`nodeId`), приложение сразу делает
  `setNodeId` + `node/bind`, и мобильный шлюз стартует с корректным id.
- Плата без датчика батареи читала 0 % и блокировала relay/mobile-gateway.
  Теперь `0 %` считается «датчик не подключён», порог действует только для
  реальных значений.
- `publicId` из INFO больше не отправляется в `/v1/modules/pair`: прошивка
  отдавала туда `node_id` (9 цифр), из-за чего Hub отвечал
  `public_id_mismatch`. Публичный 8-значный ID назначает Hub.

## Что работает

1. Телефон с интернетом — мобильный шлюз кластера: модуль шлёт uplink в BLE,
   приложение пересылает в `POST /v1/kmesh/v1/mobile/relay`, а downlink
   забирает из `GET /v1/kmesh/v1/mobile/downlink` и отдаёт модулю.
2. Прошивка включает mobile-gateway по `INET_STATUS` и отдаёт `gateway=true`
   в INFO — капсула «Соединение» скрыта, когда Hub реально доступен.
3. Без интернета у телефона узел работает через ESP32-шлюз; маршрут больше не
   сбрасывается periodic rescan'ом, beacon'ы каждые 5 с.

## Прошивка 153

- legacy INFO: `nodeId`, без фиктивного `publicId`;
- `set_battery(0)` не блокирует relay;
- INFO: `bcn`, `gwAge`, `ch`, `mobile` для диагностики.
