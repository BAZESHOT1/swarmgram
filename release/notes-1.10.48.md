# Klinto 1.10.48 — сохранность личных сообщений из KMesh и поиск без Hub

Включает всё из 1.10.47 (ключ пары пользователей, серверный ключ из кэша, без открытого текста).

## Сообщения под ключом пары → серверная копия
- **Отправитель, Hub через шлюз KMesh** (у телефона нет интернета): как только модуль видит шлюз, сообщения,
  ушедшие под ключом пары, переотправляются под постоянным серверным ключом чата с тем же msgUuid — Hub сохраняет
  их как обычные сообщения у обоих собеседников.
- **Отправитель, интернет**: очередь выгружается на `/kmesh/v1/sync` под серверным ключом (как раньше).

## Синхронизация силами получателя
- Отправитель подписывает сообщение ключом устройства (ECDSA P-256):
  `klinto-relay-v1|msgUuid|chatId|ts|sha256(text)`; подпись едет внутри зашифрованной нагрузки.
- Получатель сохраняет текст и подпись в очередь пересылки и при доступе к Hub выгружает копию под серверным
  ключом на новый `POST /v1/kmesh/v1/relay-sync`.
- Hub 1.4.6 находит автора по ключам устройств участников чата, расшифровывает копию и сверяет хеш текста —
  создать или подменить чужое сообщение без ключа устройства автора нельзя. Дубли отсекаются по msgUuid.
- Ограничение: подпись помещается в пакет KMesh для текстов примерно до 60–70 символов; длинные сообщения
  сохраняются через очередь отправителя.

## Поиск без Hub
- Запрос поиска уходит и на Hub (через шлюз), и широковещательно в кластер (LOCAL_SEARCH_REQ 0x20).
- Телефоны, получившие запрос через свои модули, отвечают только публичным: свой @username и публичные
  группы/каналы из своего списка (LOCAL_SEARCH_RESP 0x21). Результаты показываются в секции «Из модуля».
- Дальность — в пределах кластера и ретрансляторов (TTL пакета); межкластерной передачи пока нет.
