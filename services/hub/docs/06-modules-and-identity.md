# Модули: личность, владение, обновления

## Три идентификатора

1. **Название** — отображаемое имя (до 15 символов), задаётся при прошивке или переименовании; видно на карте и в списке.
2. **MAC** (eFuse, `esp32-<12 hex>`) — привязка и защита от кражи: модуль принадлежит аккаунту по MAC. `mod6` — последние 3 байта.
3. **UUID/префикс владельца** — в BLE-имени `KL-<PREFIX8>-<MOD6>` (`PREFIX8` из `user_net_identities.ble_prefix`). По нему приложение мгновенно узнаёт свои модули без интернета. Свободный модуль рекламируется как `KL-00000000-<MOD6>`.

`nodeId` модуля = FNV-1a от hex-MAC с битовой маской (`kl_node_id_from_mac()` в прошивке, `nodeIdFromMac()` в клиенте) — по нему модуль находится на карте.

## Владение и передача

- Привязка: `POST /kmesh/v1/modules/claim` (MAC → `user_modules`, выдаётся `claimToken` — подписанное подтверждение владельца для модуля).
- Удаление: `DELETE /kmesh/v1/modules/:mac` (только владелец; работает и для модулей, о которых нет данных).
- Переименование: `PATCH /kmesh/v1/modules/:mac`.
- Передача чужому аккаунту — только через контракт `module_transfer_contracts` с подтверждением старого владельца (`transfer/request`, `accept`, `reject`, `cancel`).
- Чужие и свободные модули приложение **не подключает автоматически** и не показывает по ним уведомления.

## Обновление прошивки

- Модуль: `firmware = "<VERSION>/<BUILD>"`.
- Hub: `firmware_releases.version` в том же формате, обновляется после каждой успешной серверной сборки.
- Клиент показывает «обновление», если номер сборки на сервере строго больше. Старые релизы без номера сравниваются по версии.
- Способы обновить: OTA по сети (`ModuleOtaSheet`), прошивка по USB (мастер), `/kmesh/v1/ota/*` для плана и патчей.

## Удалённая настройка (план, этап 4)

Тип модуля, распиновка (делитель батареи, LoRa-чип и пины), мощность ESP-NOW и LoRa — по BLE/USB/kMesh командами, подписанными владельцем; значения хранятся в NVS, перепрошивка не нужна.
