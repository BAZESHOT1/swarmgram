# Модули: личность, владение, обновления

## Три идентификатора

1. **Название** — отображаемое имя (до 15 символов), задаётся при прошивке или переименовании; видно на карте и в списке.
2. **MAC** (eFuse, `esp32-<12 hex>`) — привязка и защита от кражи: модуль принадлежит аккаунту по MAC. `mod6` — последние 3 байта.
3. **UUID/префикс владельца** — в BLE-имени `KL-<PREFIX8>-<MOD6>` (`PREFIX8` из `user_net_identities.ble_prefix`). По нему приложение мгновенно узнаёт свои модули без интернета. Свободный модуль рекламируется как `KL-00000000-<MOD6>`.

`nodeId` модуля = FNV-1a от hex-MAC с битовой маской (`kl_node_id_from_mac()` в прошивке, `nodeIdFromMac()` в клиенте) — по нему модуль находится на карте.

## Владение и передача

- Привязка: `POST /kmesh/v1/modules/claim` (MAC → `user_modules`, выдаётся `claimToken` — подписанное подтверждение владельца для модуля).
- Удаление: `DELETE /kmesh/v1/modules/:mac` (только владелец; работает и для модулей, о которых нет данных).
- Переименование: `PATCH /kmesh/v1/modules/:mac`.
- Передача чужому аккаунту — только через контракт `module_transfer_contracts` с подтверждением старого владельца (`transfer/request`, `accept`, `reject`, `cancel`).
- Чужие и свободные модули приложение **не подключает автоматически** и не показывает по ним уведомления.

## Том данных модуля (прошивка 178+)

Память модуля: два OTA-слота приложения (`app0`/`app1` — основная прошивка и слот обновления) и NVS — данные модуля. В NVS хранится всё, что нужно для работы после обновления: владелец (`klinto3`: префикс, net id, эпоха, имя), транспорты (`hw/if`), LoRa (чип `lc`, пины `ls`, мощность `lw`), делитель батареи (`bp`, `br`), светодиод (`ld`), мощность ESP-NOW (`ep`), тип (`rl`), Wi‑Fi шлюза (`wifi`). При первом запуске 178 значения переносятся из сборки (`hw/seed`), дальше NVS главнее сборки. Поэтому OTA-образ общий для всех модулей одного чипа и варианта.

Важно: модули на прошивке до 178 нужно один раз прошить по USB сборкой 178+, иначе общий OTA-образ не знает их пинов и настроек.

## OTA по kMesh (прошивка 178+)

1. Админка → OTA → «Собрать релиз»: Hub собирает канонические образы текущей прошивки для выбранных чипов, два варианта — узел (BLE) и шлюз (Wi‑Fi/HTTP); подпись манифеста включает вариант.
2. «Раскатка»: выбор кластеров (шлюзов или «все») и транспортов раздачи (ESP-NOW, LoRa).
3. Шлюз кластера раз в 2 минуты спрашивает Hub. Если раскатка его касается, сначала обновляется сам (полный образ по Wi‑Fi прямо в слот), затем по плану кластера раздаёт образы узлам: дельта-патч, если есть, иначе полный образ окнами по HTTP Range (не храня его целиком).
4. Узел пишет полный образ прямо в неактивный слот, проверяет подпись и SHA-256, перезагружается. После подтверждения он 6 минут сам раздаёт свой образ соседям того же чипа и варианта — каскад. OTA-пакеты не ретранслируются (TTL 1) и идут только по выбранным транспортам.
5. **Защита от сломанной прошивки.** Перед перезагрузкой модуль запоминает транспорты, по которым слышал сеть последние 10 минут. Новая прошивка подтверждается, только когда по каждому из них снова пришли пакеты (шлюз — ещё и ответ Hub). Нет связи 10 минут или три неудачных запуска подряд — откат на прошлый слот, сборка помечается сломанной и больше не ставится.

Скорость: полный образ ~1.4 МБ по ESP-NOW — минуты на хоп; по LoRa — часы (дельта-патчи меньше).

## Обновление прошивки

- Модуль: `firmware = "<VERSION>/<BUILD>"`.
- Hub: `firmware_releases.version` в том же формате, обновляется после каждой успешной серверной сборки.
- Клиент показывает «обновление», если номер сборки на сервере строго больше. Старые релизы без номера сравниваются по версии.
- Способы обновить: OTA по сети (`ModuleOtaSheet`), прошивка по USB (мастер), `/kmesh/v1/ota/*` для плана и патчей.

## Удалённая настройка железа (прошивка 177+; транспорты и светодиод — 178+)

Что можно менять без перепрошивки: тип (носимый ↔ ретранслятор), делитель батареи (пин и коэффициент; пусто — батареи нет), LoRa-чип (SX1262, SX1278, SX1276, LR2021) и семь пинов (SCK, MISO, MOSI, CS, RST, IRQ, BUSY), мощность ESP-NOW (2–21 дБм) и LoRa (2–22 дБм). Шлюз не превращается в другой тип без перепрошивки; LoRa нельзя «добавить», если прошивка собрана без неё (INFO: `hw.lb = 0`).

**Подпись владельца.** Приложение просит у Hub `POST /kmesh/v1/modules/:mac/config` с параметрами `p`; Hub проверяет, что MAC принадлежит пользователю, и подписывает ключом OTA (ECDSA P-256, DER) строку `KLINTO-CFG1|<mod6>|<epoch>|<p>`. `epoch` — время в секундах и строго растёт: модуль принимает команду, только если эпоха больше сохранённой (`hw_epoch`), поэтому старую команду повторить нельзя. Подпись привязана к `mod6`, чужому модулю её не применить.

**Формат `p`** (все части необязательны): `b=<пин>,<коэф×100>;c=<чип 0..3>;l=<sck>,<miso>,<mosi>,<cs>,<rst>,<irq>,<busy>;e=<дБм>;w=<дБм>;r=<c|r>;i=<1|2|3>;d=<пин светодиода>`. Чип: 0 — SX1278, 1 — SX1262, 2 — SX1276, 3 — LR2021.

**Доставка:**

- напрямую по BLE/USB — кадр CONFIG с JSON `{"hw":"<p>","e":<epoch>,"s":"<sig hex>"}`;
- через Hub, если телефон не подключён к модулю: Hub ставит пакет в downlink шлюза, у которого модуль был слышен за 30 минут (`deliver: "hub"`);
- по mesh другому узлу — RPC 0x30 (`KL_RPC_NODE_CONFIG`) через подключённый носимый: `[epoch u32][sig_len u8][sig][p]`, пакет шифруется общим mesh-ключом, получатель проверяет подпись.

Модуль сохраняет значения в NVS (пространство `hw`), печатает `[klinto] hw config applied` и перезагружается; при загрузке значения `hw` перекрывают сборку. Текущие значения модуль отдаёт в INFO: `"hw":{"b","r","c","l":[7],"e","w","lb","he"}`.

Ограничения: подпись выдаёт только Hub, поэтому для настройки нужен интернет; пока владельческая подпись Wi‑Fi-настройки шлюза (`wifiSsid`/`wifiPassword`) в старом пути не требуется — это отдельный нерешённый вопрос безопасности.
