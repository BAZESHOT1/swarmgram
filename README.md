# Klinto

Мессенджер нового поколения с децентрализованным хранением: **главный сервер — оркестратор, пользовательские узлы — хранилище**.

```
Клиент ──► Главный сервер (Hub) ──► маршрут/тикет ──► Узлы пользователей ──► Клиент
                (оркестратор)                          (только шифротексты)
```

- Сообщения и медиа хранятся на узлах **в зашифрованном виде, в 3 экземплярах**.
- Ключи шифрования хранятся **только на устройствах пользователей**.
- Hub знает маршруты, метаданные и статусы узлов, но **не может прочитать содержимое**.
- Любой пользователь может поднять узел одним `docker compose up -d`.

## Состав репозитория

```
services/hub/    — главный сервер (оркестратор): аккаунты, чаты, репликация, мониторинг
services/node/   — образ узла хранения (для серверов пользователей)
services/firmware-builder/ — сборка прошивок ESP32 (arduino-cli)
client/          — Expo/React Native клиент: web, iOS, Android
docs/            — архитектура mesh-модулей и эксплуатация
```

## Быстрый старт (главный сервер)

```bash
cp .env.example .env          # заполнить секреты
docker compose -f docker-compose.hub.yml up -d --build
```

- Веб-клиент: `http://<IP>:3000`
- API: `http://<IP>:8080/v1/...`
- Проверка: `curl http://<IP>:8080/health`

## Быстрый старт (узел на своём сервере)

1. В клиенте: профиль → «Мои узлы» → **Создать токен привязки** (живёт 30 минут).
2. На своём сервере:

```bash
cp node.env.example .env
# MAIN_SERVER_URL уже прописан; указать OWNER_USERNAME и NODE_CLAIM_TOKEN
docker compose -f docker-compose.node.yml up -d
```

Узел сам регистрируется в Hub, получает `node_id` + секрет подписи тикетов и начинает слать heartbeat.

## Гибридный носимый узел KMesh_v1

Каждый носимый модуль по умолчанию — **клиент + умный ретранслятор + мобильный шлюз**.
Гибридный режим включается в прошивке для роли `NODE_CLIENT` и отключается
в настройках приложения.

- **Smart Portable Relay.** Транзит чужих пакетов разрешён всем носимым узлам,
  но с роль-штрафом к RSSI-backoff: `+60 мс` для ESP-NOW и `+250 мс` для LoRa.
  Стационарные ретрансляторы и шлюзы передают первыми; носимый узел отменяет
  свою ретрансляцию, если услышал тот же пакет от стационарного узла.
- **Battery Guard.** При заряде `< 20%` (без зарядки) транзит и мобильный шлюз
  отключаются, остаются только сообщения владельца. При `> 25%` гибридный режим
  возвращается. Зарядка снимает ограничение.
- **Mobile Smartphone Gateway.** Телефон с интернетом превращает подключённый
  по BLE модуль в шлюз: раз в 15 секунд отправляется
  `INET_STATUS {has_internet, rtt_ms, allow_relay}`. Модуль вещает `GW_BEACON`
  с `hop_count = 2` (стационарные шлюзы всегда приоритетнее), интервал маяка
  25 секунд, TTL маршрута 60 секунд — быстрый хэндовер, когда прохожий уехал.
- **Zero-Trust.** Uplink/Downlink идут кадрами `PROXY_UP`/`PROXY_DOWN`;
  телефон — «слепой курьер» и не читает шифртекст. Дневной лимит
  проксированного трафика — 10 МБ (настраивается).

### Мессенджер через радиосеть

Бинарный `PayloadCodec` (Unishox2 + компактные структуры) поддерживает полный
набор функций без интернета на телефоне:

| RPC | Назначение |
| --- | --- |
| `RPC_SEARCH_REQ/RESP` | поиск пользователей, групп и каналов (до 5 результатов) |
| `RPC_FEED_SYNC_REQ/RESP` | дельта ленты: топ-5 чатов, непрочитанные, превью |
| `RPC_CHAT_HISTORY_REQ/RESP` | последние 5–10 сообщений открытого чата |

Групповые и канальные сообщения идут с `dst_id = BROADCAST` и флагом
`IS_GROUP_OR_CHANNEL`; любой шлюз делает `Shadow Copy` и публикует сообщение
на Hub. Все сервисные RPC имеют `PRIORITY_LOW`, поэтому не блокируют личные
сообщения (`PRIORITY_MEDIUM`) и `ACK` (`PRIORITY_HIGH`).

Hub отдаёт эти данные через `/v1/kmesh/v1/*` (`search`, `feed`, `history`,
`channel/gateways`, `mobile/archive`, `mobile/presence`, `node/bind`).

## iOS-сборка без Apple Developer аккаунта

GitHub Actions workflow [`.github/workflows/ios-unsigned.yml`](.github/workflows/ios-unsigned.yml)
собирает **unsigned IPA** для реального iPhone (`arm64`, Release). Apple-аккаунт
для сборки не нужен.

1. Запустить workflow **iOS unsigned IPA** (вручную или push в `main`).
2. Скачать артефакт `Klinto-unsigned-ipa`.
3. Установить через **Sideloadly** на iPhone, войдя своим Apple ID — Sideloadly
   подпишет приложение самоподписанным сертификатом.

Ограничения бесплатной подписи: приложение нужно переподписывать раз в 7 дней,
BLE работает только в native-сборке (Expo Go и Safari не поддерживают BLE).
API-адрес нативного клиента: `https://api.klinto.is-a.dev/api`
(затем `api.klinto.io`, резервный `https://150-251-143-212.nip.io:3443/api`;
Let's Encrypt; HTTP на iOS блокируется ATS).
